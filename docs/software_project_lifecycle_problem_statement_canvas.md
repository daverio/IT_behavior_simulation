# Slide 1 — Problem Statement Canvas

## Initial Problem Statement

### 1. Nature of Software Projects

Software projects are complex socio-economic-technical systems emerging from continuous interactions between people, organizations, financial constraints, market forces, technological ecosystems, software architecture, and development processes.

Their evolution cannot be understood solely through code complexity or project management metrics. Software systems evolve simultaneously across technical, organizational, and economic dimensions.

### 2. Complexity and Non-Linearity

Software project dynamics are inherently non-linear and highly complex. Interactions between technical, organizational, economic, and human factors create feedback loops where local decisions may produce significant long-term effects on maintainability, productivity, software quality, and project sustainability.

However, a central hypothesis of this project is that these systems are not chaotic in the strict mathematical sense. In other words, small variations in initial conditions do not necessarily generate completely divergent lifecycle trajectories.

Under this assumption, software project lifecycles can be considered sufficiently well-posed to be modeled and simulated. Despite their complexity, such systems may still exhibit underlying structural regularities and systemic patterns that can be studied computationally.

### 3. Current Limitation

In practice, the different dimensions of software projects are often analyzed and managed separately.

Features, bugs, architecture, product management, finance, marketing, hiring, and organizational processes are typically treated as independent optimization problems.

However, these dimensions are deeply interconnected through feedback loops and delayed effects.

For example:

- Product pressure may increase feature velocity while accelerating technical debt accumulation
- Hiring may temporarily reduce productivity due to onboarding overhead
- Architectural degradation may progressively slow feature delivery and increase operational costs
- Marketing success may increase customer adoption, bug reporting volume, and support workload

As a result, decisions that appear locally beneficial in the short term may produce undesirable long-term consequences.

Current software engineering and project management approaches provide limited ability to understand these long-term interactions and their impact on software project evolution.

Organizations therefore lack frameworks capable of studying software projects as interconnected evolving systems.

### 4. Data Availability Problem

One major difficulty is the scarcity of large-scale structured datasets describing the complete lifecycle evolution of software projects.

Most available observations are:

- Fragmented
- Organization-specific
- Short-lived
- Incomplete
- Difficult to compare across projects

This severely limits the ability to perform large-scale empirical analysis of software lifecycle dynamics.

### 5. Simulation Model Hypothesis

The central premise of this project is that software project lifecycles can be represented through a computational simulation model capturing the interactions between technical, organizational, economic, and human factors.

Within this hypothesis, simulation is not merely a visualization or analysis tool, but the core artifact of the project itself.

The objective is to build a simulation model capable of:

- Representing the evolution of software projects over time
- Capturing non-linear interactions between project variables
- Studying the emergence of technical debt and organizational complexity
- Exploring different lifecycle trajectories
- Identifying recurring structural patterns
- Generating large-scale synthetic lifecycle data

The simulation model is therefore intended both as:

1. A research instrument for studying software project dynamics
2. A synthetic environment for generating statistical observations

The generated simulation data could later be compared with observations from real software projects in order to:

- Validate modeling assumptions
- Identify recurring behaviors
- Refine systemic hypotheses
- Better understand software evolution mechanisms

### 6. Core Research Direction

The objective of this project is to design and develop a software project lifecycle simulation model and its associated simulation framework capable of representing the long-term dynamics emerging from interactions between technical, organizational, economic, and human factors.

## Alternative Problem Statements

### Option A

How might we simulate the long-term evolution of software projects in order to better understand the emergence of technical debt and architectural degradation?

### Option B

How might we model the interaction between technical, organizational, and economic factors throughout the software project lifecycle?

### Option C

How might we study the long-term sustainability and evolution of software projects as complex systems?

### Option D

How might we allocate resources optimally in software development projects while accounting for long-term systemic effects and feedback loops?

---

## Selected Problem Statement

> How might we simulate the lifecycle of software projects to understand and predict the long-term effects of architectural decisions, technical debt, organizational dynamics, and AI-assisted development on software sustainability?

---

## Refined Problem Statement (How-User-While)

> How might we help software architects, engineering leaders, product managers, project managers, and finance managers take better long-term decisions throughout software project evolution while balancing resource allocation, market constraints, financial constraints, architectural coherence, and long-term economic sustainability?

---

## SMART Objectives

### Specific

Develop a simulation framework modeling software project evolution as a socio-economico-technical system.

### Measurable

Measure indicators such as:

- Technical debt growth
- Maintainability
- Delivery speed
- Knowledge distribution
- Architectural coherence

### Achievable

Use a simulation framework capturing the most relevant non-linear interactions and feedback loops governing software project evolution.

### Relevant

Provide a decision-support tool helping stakeholders better understand the long-term consequences of project decisions, improve predictability, and reduce systemic project risks.

### Time-bound

Deliver an initial simulation prototype capable of modeling lifecycle dynamics within the project timeframe.
